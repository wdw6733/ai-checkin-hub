# AI Checkin Hub

AI 中转 / 公益站点的一站式导航与额度看板。一个 8888 端口的控制台，管住所有站点的「入口在哪、还剩多少额度、有哪些模型能用」。

## 它解决什么问题

手里同时有多个 OpenAI 兼容中转站时，常见麻烦是：入口散落在书签里、余额要去每个站单独看、可用模型清单各不相同。本项目把这些收敛成一套统一的数据模型：

- **站点导航**：站点名称与域名都是外链，点一下就在新标签页打开站点，签到由你在站点页面手动完成
- **额度看板**：按各站 `quota_per_unit` 统一折算成美元，跨站汇总
- **模型目录**：拉取公开定价（输入/输出每百万 token）与当前 Key 真实可用的模型
- **凭据加密**：Token、Cookie、密码一律 Fernet 加密落库，接口只返回掩码
- **余额通知**：每日余额汇总推送到企业微信 / 钉钉 / 飞书 / ntfy / 任意 JSON Webhook

> 本项目**不执行任何自动签到**，也**不模拟站点登录**。它只负责两件事：把站点入口聚合到一个页面，以及用你自己提供的凭据读取余额与模型信息。

## 架构

```
                    ┌──────────────────────────────┐
   Browser ────────▶│ FastAPI (8888) 单页控制台     │
                    │  · 会话 HMAC Cookie           │
                    │  · REST API                   │
                    └───────────┬──────────────────┘
                                │
                    ┌───────────┴───────────┐
                    ▼                       ▼
            ┌──────────────┐        ┌──────────────┐
            │ 定时任务      │        │ 适配层 httpx  │
            │ 每日刷新余额  │───────▶│ 只读接口      │
            │ 每日汇总推送  │        │ 余额/定价/模型│
            └──────────────┘        └──────┬───────┘
                                           ▼
                                   ┌──────────────┐
                                   │ SQLite /data │
                                   │ 配置·快照     │
                                   └──────────────┘
```

**为什么只做只读**：签到接口在各站点的路径、参数、风控策略差异很大，且频繁改动。与其维护一堆易失效的自动化脚本，不如把「入口」和「余额」做扎实——签到这一步交回给你在站点页面点一下，成本很低且不会误触发风控。

## 部署

```bash
git clone https://github.com/wdw6733/ai-checkin-hub.git
cd ai-checkin-hub
cp .env.example .env
# 编辑 .env，把 WEB_PASSWORD 改掉
docker compose up -d
```

打开 `http://<服务器IP>:8888`，用 `WEB_PASSWORD` 登录。数据全部落在 `./data`：`app.db`（SQLite）、`secret.key`（加密密钥）。**备份就备份这一个目录**。

自行构建：

```bash
docker compose up -d --build
```

## 添加站点

点「+ 添加站点」，填名称与 Base URL（`https://xxx/v1` 或 `https://xxx` 都可以，会自动规范化），可选填一个账号凭据：

| 认证方式 | 填什么 | 用途 |
|---|---|---|
| **API Key / 访问令牌** | `sk-...`（站点「设置 → 令牌」生成的系统访问令牌） | 最稳，优先推荐 |
| **浏览器 Cookie** | `session=xxx; other=yyy` | 万能兜底 |
| **账号密码** | 用户名 + 密码 | 站点未开验证码时可用 |
| **linux.do Cookie（`_t`）** | linux.do 的 `_t` Cookie 值 | 兼容旧配置 |

凭据**只用于读取余额、模型数与定价**，不参与任何自动化操作。保存后会自动探测框架并写回。

获取凭据：登录站点 → F12 → Network → 任一 `/api/` 请求 → 复制 `Authorization: Bearer xxx` 或完整 Cookie 头。

## 手动签到

站点页与概览页的站点卡片都支持直接跳转：

- 概览页：整张卡片可点，新标签页打开站点
- 站点页：点**站点名称**或**域名**，或点操作栏的「打开站点」
- 打开后在该站点页面完成签到即可，回到面板点「刷新余额」同步最新额度

## 定时任务

| 任务 | 时间 | 说明 |
|---|---|---|
| 余额刷新 | 每日 12:10 | 受设置页「每日 12:10 刷新余额」开关控制 |
| 余额汇总 | 每日 22:30 | 把各站余额推送到配置的 Webhook |

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | 登录，返回会话 Cookie |
| GET | `/api/overview` | 汇总指标 + 站点快捷入口 |
| GET/POST | `/api/sites` | 站点列表 / 新建 |
| PATCH/DELETE | `/api/sites/{id}` | 修改 / 删除（级联账号） |
| POST | `/api/sites/{id}/probe` | 探测框架、WAF、公开定价 |
| GET | `/api/sites/{id}/models` | 定价与可用模型 |
| POST | `/api/sites/{id}/accounts` | 添加账号 |
| PATCH/DELETE | `/api/accounts/{id}` | 修改 / 删除账号 |
| POST | `/api/accounts/{id}/refresh` | 刷新余额与模型数 |
| POST | `/api/accounts/refresh-all` | 刷新全部账号余额 |
| GET | `/api/logs` | 运行日志 |
| GET/PUT | `/api/settings` | Webhook 与每日刷新开关 |
| GET | `/healthz` | 容器健康检查 |

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `WEB_PASSWORD` | `admin` | 控制台密码，**必须改** |
| `SECRET_KEY` | 自动生成 | Fernet 密钥，固定它可让备份在异地解密 |
| `DATA_DIR` | `/data` | 持久化目录 |
| `MAX_CONCURRENCY` | `4` | 余额刷新并发上限 |
| `HTTP_TIMEOUT` | `25` | 单请求超时（秒） |
| `VERIFY_SSL` | `false` | 是否校验站点证书 |

## 风险与边界

- **本工具不绕过登录、不自动签到**：所有请求都使用你自己提供的合法凭据，只访问只读接口。
- **余额汇率是近似值**：按站点公开的 `quota_per_unit` 折算，站点若自定义倍率或分组定价，实际扣费可能不同。
- **只支持标准 New API 系的只读接口**：`/api/user/self`、`/api/pricing` 等路径不标准的站点，余额与模型可能拉取失败，但不影响站点导航功能。
- **不要把这套东西部署在公网无防护环境**：至少改掉默认密码，最好只在内网或加一层反代鉴权。
